JAMF Pro Heal: A Safer Self-Healing Workflow for Managed Macs

JAMF Pro Heal is a production-style self-healing design for Jamf-managed Macs. Its core idea is simple: do not run destructive Jamf cleanup just because the network is bad.

Project article · Jamf Pro · macOS · LaunchDaemon · SwiftDialog · MDM repair

Article index

Problem
Jamf failures can look like local client problems when the real issue is Wi-Fi, DNS, VPN, proxy, or Jamf Cloud reachability.

01 · Why

Not every Jamf failure is a Jamf failure

In a real Mac fleet, jamf checkJSSConnection can fail for reasons that have nothing to do with the local Jamf framework. A captive portal, slow internet, DNS failure, VPN issue, proxy problem, SSL inspection, or temporary Jamf Cloud reachability issue can all look like a management failure from the endpoint.

JAMF Pro Heal is designed around that risk. It checks network and Jamf URL health before allowing any local cleanup, so a temporary connectivity issue does not become a destructive repair event.

02 · Architecture

A root checker, a user prompt, and a separate repair runner

The workflow separates responsibility across launchd components. A LaunchDaemon runs a lightweight hourly health check as root. A LaunchAgent handles user messaging in the logged-in session. A second LaunchDaemon watches for an approval flag and runs the full repair script as root only after the user chooses to proceed. 

Every 1 hour
↓
Health checker classifies network, Jamf URL, local Jamf, and MDM state
↓
Network issue: notify only, do not repair
↓
Repairable local issue: notify first
↓
After 2 days: show SwiftDialog repair prompt
↓
User approves
↓
Root runner starts full repair

03 · Classification

The classifier is the safety gate

The hourly health check classifies results into states such as GOOD, NETWORK_ISSUE, SLOW_INTERNET, JAMF_CONNECTIVITY_ISSUE, JAMF_CLIENT_BROKEN, MDM_PROFILE_MISSING, and JAMF_CLIENT_OR_TRUST_ISSUE.

  • Network, speed, DNS, HTTPS, VPN, proxy, or Jamf URL reachability issues do not unlock repair.
  • Missing Jamf binary, missing plist, wrong Jamf URL, missing MDM profile, or local trust failure can unlock repair.
  • The tool stores issue type, reason, first detected time, last detected time, and whether repair is allowed.

04 · User experience

Soft notification first, stronger prompt later

For the first two days, repairable issues show native macOS notifications. This avoids alarming users for short-lived conditions. If the issue remains for more than two days, SwiftDialog shows a stronger prompt with a clear Run Repair Now action.

The user prompt never performs privileged work directly. It only writes an approval flag. The root LaunchDaemon sees the flag and runs the repair workflow.

05 · Repair

Repair is deliberate, not automatic cleanup

Before repair starts, the full repair script validates general internet and Jamf URL connectivity again. If the network is unstable, it aborts. If checks pass, it can clean broken Jamf components, attempt MDM cleanup, make the current logged-in user local admin for the enrollment flow, trigger ADE re-enrollment, open Profiles / Device Management, guide the user through SSO, and validate MDM enrollment afterward.

Safety note

The workflow is proactive. It should be deployed before a device is fully broken. If MDM is already gone, the user is not admin, and no root-capable tool remains, recovery needs another path.

06 · Deployment

Installed as a small managed Mac subsystem

The project installs scripts under Application Support, registers LaunchDaemons and a LaunchAgent, stores state under /var/db, and writes logs for audit and troubleshooting. 

/Library/Application Support/BD/JamfRepair/
/Library/LaunchDaemons/com.bd.jamf.healthcheck.plist
/Library/LaunchDaemons/com.bd.jamf.repair.runner.plist
/Library/LaunchAgents/com.bd.jamf.repair.prompt.plist
/var/db/com.bd.jamfrepair/

sudo ./install.sh
sudo ./uninstall.sh

07 · What this solves

A safer repair path for IT and users

The value is not just automation. It is restraint. JAMF Pro Heal gives IT teams hourly visibility, fewer false repair attempts, a clean user approval flow, root repair execution without permanent admin elevation, and logs that explain why repair did or did not happen.

For the user, it turns a complex management failure into a guided flow: notification, clear prompt, enrollment guidance, and validation.
