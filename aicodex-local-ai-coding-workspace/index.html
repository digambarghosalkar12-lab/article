Building a Local Codex-Like AI Coding Workspace on Mac

aicodex is a local-first AI coding command center for Mac. It combines Ollama, Aider, Open WebUI, model routing, safe MCP tools, Git hygiene, and project memory into one repeatable workflow.

01 · Why

Why build this locally?

Cloud coding agents are powerful, but they are not always the right fit for private experiments, offline-friendly work, model-control testing, or projects where code should stay on your machine. The question behind aicodex was simple: can a Mac run a practical Codex-like workflow locally?

The answer is not a perfect replacement for managed cloud agents. But it can become a very useful local workspace where the project, models, rules, memory, and Git history remain under your control.

02 · What it is

aicodex as a local command center

aicodex is a launcher and workflow wrapper. The main command, aicodex run, prepares the selected project, starts the local AI services, opens a GUI, and can launch Aider for repo edits.

  • Ollama runs local language and vision models.
  • Aider acts as the repository editing agent with visible diffs.
  • Open WebUI gives a browser-based chat interface.
  • Smart Router selects a model based on the task type.
  • Safe MCP tools expose controlled filesystem, Git, and shell access.
  • Project memory keeps reusable context across sessions.

03 · Architecture

The workflow behind the launcher

When the setup is working, aicodex creates a predictable local loop: validate the tool, select a project, check hygiene, restore or generate memory, start Ollama, start the router, open the GUI, and optionally launch Aider. 

aicodex run
↓
validate tool setup
↓
select project
↓
project hygiene + memory restore
↓
start Ollama + smart router + Open WebUI
↓
open project workspace
↓
archive memory on exit

04 · Model routing

One model should not do every job

The router lets the GUI talk to a single local endpoint while still choosing different models for different work. Code generation can go to a coding model, architecture review can go to a reasoning model, screenshots can go to a vision model, and smaller jobs can use lighter fallbacks. 

Open WebUI
Base URL: http://127.0.0.1:5050/v1
Model: smart-auto

Code task      → Qwen coder model
Architecture   → reasoning model
Screenshot     → vision model
Memory search  → embedding model

05 · Safety

Project hygiene before AI touches code

The most important design choice is not the model. It is the safety wrapper around project work. aicodex checks whether the project is a Git repo, whether there is a baseline commit, whether the working tree is dirty, whether memory files exist, and whether obvious secret files are present.

  • Tool issues can trigger repair or reset of the tool itself.
  • Project issues create hygiene prompts instead of resetting the tool.
  • Safe MCP commands are allowlisted and dangerous commands are blocked.
  • Memory archives stay local and can be restored when reopening a project.

Design note

This is not a perfect sandbox, but it is a meaningful improvement over handing an AI unrestricted shell access. The system is designed around local ownership, Git visibility, and narrower tool access.

06 · Daily use

A practical local AI coding loop

The normal flow is intentionally simple: start the launcher, use the GUI for thinking and review, use Aider for actual repo edits, inspect the diff, run tests, commit, and let project memory archive when the session ends. 

aicodex mode fast
aicodex pull-models fast
aicodex run

# later, when stable
aicodex kill
aicodex mode balanced
aicodex pull-models balanced
aicodex run

07 · What it does not replace

Local-first has tradeoffs

aicodex does not fully replace managed cloud coding agents, cloud sandboxes, enterprise workspace controls, or polished multi-agent orchestration. It is strongest when the goal is private local coding, learning how coding agents work, generating scripts, reviewing architecture, editing repos, and building repeatable project workflows.

The value is control: your Mac, your models, your project, your Git history, and your local memory.
