Your first lines of code with a local LLM.

Set up a small Python project, connect it to Ollama, and see your own code get an answer.

September 15, 2026 · Python · uv · Ollama

Your small workshop

uv
Organises the project and its Python tools.
Ollama
Runs the language model on your computer.
Your code
Chooses the model, gives instructions, and asks a question.

Your first LLM project can be simple: write a question in Python, send it to a model on your computer, and print the answer.

Think of this setup as a small workshop. uv organises your Python tools. Ollama runs the LLM. Your Python code tells it what to do.

This walkthrough follows my qwen-agent experiment. I used qwen3:14b, but I suggest starting with the smaller qwen3:1.7b for these exercises.

1. Get the tools ready

Install uv and Ollama. Then open your terminal and check:

uv --version
ollama --version

Start Ollama, then download the model:

ollama pull qwen3:1.7b

You only need to download it once. Start small so you can spend more time experimenting. Download time and response speed depend on your computer. If Ollama is not running, use ollama serve in another terminal and leave it open.

2. Create your project

For a new project, run:

uv init qwen-agent --python 3.12
cd qwen-agent

uv init creates the project’s starting files. cd moves you into its folder.

Already have the project? Open its folder instead of creating it again.

3. Give the project its own environment

uv venv

This creates .venv, a separate toolbox for this project. Packages installed here stay separate from those used by your other projects.

We will use uv run to run Python, so you do not need to activate the environment manually. How uv manages projects.

4. Add the requirements

Requirements are ready-made Python packages your code needs:

uv add openai-agents rich
PackageWhy we use it
openai-agentsProvides Agent and Runner to define and run our assistant.
richMakes the answer easier to read with Markdown formatting. It is optional for the LLM itself.

uv records these requirements in pyproject.toml and their resolved versions in uv.lock.

If you downloaded an existing copy of this project, use uv sync to install its recorded requirements. You do not need a separate requirements.txt for this workflow.

5. Tell Python where Ollama lives

Create or open main.py. Replace its starter contents with the following imports and setup. Add the next code blocks below it as you read:

from agents import (
    Agent, Runner, AsyncOpenAI,
    OpenAIChatCompletionsModel, set_tracing_disabled,
)
from rich.console import Console
from rich.markdown import Markdown

console = Console()
set_tracing_disabled(True)

ollama_client = AsyncOpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama",
)

Think of ollama_client as the delivery service for your questions. base_url is its destination. localhost means your own computer.

Although the class is called AsyncOpenAI, this address sends requests to Ollama. The "ollama" key is a placeholder; local Ollama does not require a real OpenAI API key. Ollama’s compatibility guide.

The project also uses set_tracing_disabled(True) to turn off the SDK’s tracing for this local example.

6. Choose the model

model = OpenAIChatCompletionsModel(
    model="qwen3:1.7b",
    openai_client=ollama_client,
)

The connection says where to send the question. This block says which LLM should answer.

To switch models, change "qwen3:1.7b" to another model you have downloaded. Run ollama list to see the exact names.

Keep openai_client=ollama_client so the model uses your Ollama connection.

ModelWhen to try it
qwen3:1.7bMy suggested starting point. About 1.4 GB to download.
qwen3:0.6bA smaller option for simple experiments. About 523 MB to download.
qwen3:4bTry next if you want to compare a larger model with your first results.

Download size is not the same as memory needed while running. Small models can miss instructions or give weak answers; keep the first tasks short. To switch, download the new model with ollama pull MODEL_NAME, then put that exact name in model=.

7. Give the agent a role

agent = Agent(
    name="Local Agent",
    instructions="You are a helpful AI assistant.",
    model=model,
)

name is a label. instructions describe how the assistant should respond. model=model connects it to the model chosen above.

Start by changing only the instructions:

instructions="Explain things to a beginner. Use short sentences and one example."

In my main1.py, several agents share the same model but have different instructions. That lets me compare how the same LLM answers as a comedian or a scientist.

8. Ask a question and run it

Add this final block to send a question and display the answer:

result = Runner.run_sync(
    agent,
    "Explain what an AI agent is in simple terms."
)

console.print(Markdown(result.final_output))

Runner runs the agent. final_output contains its answer. Keep all four main code blocks in the same file, in the order shown. The instructions-only snippet is an optional edit inside Agent(...).

Run the file from your project folder:

uv run python main.py

For your first experiment, keep the question the same and change the instructions. Run it again and compare the answers. Then change the question. You are now practising the core skill: changing code, running it, and observing what the LLM does.

9. My hands-on experiment: one question, five characters

In main1.py, I asked the same question about ChatGPT to a Joker, a toddler, a Ninja, a Scientist, and a Doctor. All five used the same model. I changed the instructions for each character.

Think of one actor reading the same line in five costumes. The model stays the same; the role changes how it is asked to respond. These are separate replies, with no conversation between the characters.

To try it, copy your working main.py to main1.py. Keep the imports, console, tracing setting, ollama_client, and model setup. Replace everything from agent = Agent(...) onward with this simplified version of my experiment:

from rich.panel import Panel

Joker = Agent(
    name="Joker",
    instructions="Explain like a friendly stand-up comedian. Use three short sentences.",
    model=model,
)
Toddler = Agent(
    name="Toddler",
    instructions="Explain with very simple words and a playful example. Use three short sentences.",
    model=model,
)
Ninja = Agent(
    name="Ninja",
    instructions="Explain like a ninja teaching a new recruit. Use three short sentences.",
    model=model,
)
Scientist = Agent(
    name="Scientist",
    instructions="Explain like a scientist teaching a beginner. Use three short sentences.",
    model=model,
)
Doctor = Agent(
    name="Doctor",
    instructions="Explain the technology using a clinic analogy. Use three short sentences.",
    model=model,
)

question = "Tell me something about ChatGPT"

for character in [Joker, Toddler, Ninja, Scientist, Doctor]:
    result = Runner.run_sync(character, question)
    console.print(
        Panel(Markdown(result.final_output), title=character.name)
    )

The for loop asks each character in turn. Panel puts a labelled box around each answer. This makes five model requests, so start with two characters if you want a shorter run.

uv run python main1.py

Compare the replies: did each follow its role, stay within three sentences, and still explain the topic correctly? A confident character voice does not make an answer more accurate.

10. Make the experiment your own

Keep the same loop and give each character a new job. Try one of these:

  • A story studio: ask for a story about a lost robot. Give one agent a funny style, one a mystery style, and one a bedtime-story style.
  • A Python classroom: ask “What is a Python list?” Have one agent use a shopping-basket analogy, one give a tiny code example, and one ask you a quiz question.
  • An idea workshop: describe an imaginary café. Ask a name-maker for three names, a customer for what sounds appealing, and a critic for one improvement.
  • A language practice partner: ask for a short greeting in English, Hindi, or Marathi. Compare the result with language you know and correct any mistakes.

For a small coding challenge, replace the fixed question with question = input("Ask your characters: "). Run the file again and type a new question without editing the code.

Then try the exact same question and instructions with a different model. Note how long it takes, whether it follows your instructions, and which answer helps you most. Change one thing at a time so you can see what made the difference.
